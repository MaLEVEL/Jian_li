# 面试讲述与技术边界

> 普通用户请先阅读 [README](../README.md) 和 [求职闭环使用指南](job-loop.md)。本文用于面试表达和工程边界说明。

## 讲项目的顺序
真实痛点是针对多个 JD 重复核对技能、找素材和改简历。原项目只有浏览器规则，这次加入 Python 服务和六节点状态图，拆开解析、评分、检索与建议，使每一步可观察、可测试。演示时先分析真实 JD，逐项解释分数，再打开素材引用，最后展示批量排序和历史。

## 常见问题
- 为什么 LangGraph：状态边界清晰，节点耗时与降级可见；这是确定性工作流，不夸大成自主规划 Agent。
- 为什么不用模型直接打分：代码计算的技能覆盖率稳定且可审计；学历、软技能和真实岗位竞争不在该分数内。
- 别名如何约束：只合并同一技术的写法；Java 不匹配 JavaScript，LangChain 不自动满足 LangGraph。
- 为什么混合检索：BM25 保留精确技术词，另一条向量排序信号参与 RRF；默认稀疏向量和可选 BGE 神经向量明确区分。
- 如何约束幻觉：解析要求原文证据，建议引用素材 ID，无证据只给学习计划；模型提案仍需人工核实。
- 上游失败怎么办：Pydantic 校验 JSON，有限重试，认证失败不重试；降级报告标记 degraded，不静默伪装成功。
- 如何控制批量成本：最多 20 个岗位、默认并发 2、单项失败隔离、记录 Token；当前未实现跨 JD 模型解析缓存或预算账户。
- 数字从哪里来：运行评估 CLI，并说明数据来源和运行模式。合成回归和真实人工数据分开讲，不声称招聘转化提升。
